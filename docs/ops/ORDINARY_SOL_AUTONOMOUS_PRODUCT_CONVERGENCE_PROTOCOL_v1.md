## Why this protocol is preserved

The target operating model was distilled from Sharky's current evidence/tooling
work plus a proven ordinary-ChatGPT workflow used elsewhere. The goal is not
infrastructure for its own sake. The goal is maximum product EV per unit of
Actions/runtime/owner attention:

> ordinary GPT-5.6 Sol High performs deep comprehension, measurement,
> implementation, rendered/runtime inspection, keep/reject decisions, residual
> audits, and multiple high-EV waves autonomously for as long as material
> machine-reducible EV remains.

## Intended agent configuration

- ordinary ChatGPT
- GPT-5.6 Sol
- reasoning HIGH
- GitHub ON
- Codex OFF
- Work OFF
- no requirement for local Flutter when repository remote execution/evidence is sufficient

## Core principle

Repository-as-a-machine:

- GitHub = source/version-control control plane
- lightweight Actions lane = remote execution
- existing deterministic capture = renderer
- artifacts = evidence transport
- model vision = pixel inspection
- focused tests/geometry/runtime evidence = machine safety
- final heavy PR/native/Human gates remain separate

The agent must not claim visual truth from source alone. Actual rendered pixels
are mandatory evidence for visual claims.

## Long autonomous loop

A specially admitted macro-Gauntlet should run:

`RESOLVE TRUTH -> COMPREHENSION SWEEP -> GAP LEDGER -> SELECT #1 MATERIAL GAP -> CHEAPEST FALSIFIER -> BOUNDED HYPOTHESIS -> IMPLEMENT -> FAST REMOTE EVIDENCE -> INSPECT ACTUAL RUNTIME/PIXELS -> KEEP OR REJECT -> UPDATE LEDGERS -> RESCORE -> RESIDUAL AUDIT -> NEXT GAP -> REPEAT`

Intermediate progress reporting is not an owner gate. Continue automatically
unless a hard stop condition is reached.

## No mutation before sufficient comprehension

Before a major wave, prefer a bounded read-only sweep of final assembled/runtime
truth. Do not immediately repair the first visible symptom when the defect may
be systemic.

Audit final composition/runtime truth rather than historical source fragments
whenever feasible.

Examples:

- visual -> actual canonical rendered state
- learning flow -> actual canonical traversal/state
- telemetry -> actual emitted events
- personalization -> actual selected feedback/decision path

## Temporary observability

A Gauntlet may create bounded temporary read-only instrumentation/export/capture
helpers when existing evidence cannot answer the admitted question.

Rules:

- purpose must be explicit;
- no second source of truth;
- no architecture migration disguised as audit tooling;
- remove temporary scaffolding before final candidate unless it proves durable high EV as reusable observability;
- tests-for-tests/meta-guards remain forbidden.

## Persistent ledgers

Maintain three working ledgers during a long mission.

### BEST ledger

- current BEST exact SHA
- scorecard
- why it is the current winner
- known residuals

### Rejected hypothesis ledger

- hypothesis
- what was tried
- evidence
- why rejected
- what must not be repeated without new evidence

### Open-gap ledger

- gap
- severity
- expected EV
- confidence
- machine-reducible yes/no
- cheapest falsifier

The purpose is to prevent circular work, replay, and subjective drift over long
sessions.

## Evidence economics: three speeds

### K0 - Kaizen feedback

Use repeatedly inside the autonomous loop:

- exact candidate SHA
- minimal focused analyzer/tests
- existing deterministic runtime/render capture
- small diff-adaptive PNG/evidence artifact
- no PR requirement if a dedicated branch-push lane exists
- no Cloudflare/native/full release gate

### K1 - Retained major-wave acceptance

Use after a meaningful candidate wins:

- broader focused regression
- representative portrait/state matrix
- canonical route proof where relevant
- still cheaper than full release/native

### K2 - Final admission

Use once on the final retained candidate:

- normal PR/full required CI
- exact-main proof where required
- native proof where authority requires it
- Human/HNP later where evidence class requires it

Heavy CI must not become the inner development loop.

## Diff-adaptive evidence

Do not always capture the same arbitrary screens. Prefer:

- a small constant sentinel set;
- plus 1-3 states/surfaces selected from changed ownership or the active hypothesis.

Keep evidence capped. More screenshots are not automatically better.

## Work while remote evidence runs

Never idle merely because a remote render/check is running if independent
read-only analysis remains useful.

Allowed while waiting:

- ownership/risk research
- benchmark review
- next-gap preparation
- scorecard updates

Forbidden while waiting:

- mutating the next candidate before the current candidate is adjudicated

## Wave size and repair policy

Prefer large coherent product-EV steps over micro-polish.

Per hypothesis:

- normally up to 2-3 evidence-driven attempts;
- if it cannot win, reject/revert the hypothesis and move to the next admitted gap;
- do not consume unlimited iterations trying to rescue one idea.

Across a specially admitted macro mission, multiple hypotheses/waves may run
without owner interruption.

## Monotonic quality rule

A new candidate becomes BEST only if:

- the target gap improves materially;
- no material regression appears on protected axes;
- semantic/poker/runtime truth remains valid;
- implementation complexity is proportionate to EV.

When uncertain, retain the previous BEST. Newer does not imply better.

## Residual audit after every major win

A green wave is not proof that the product is finished. After each major
retained wave, perform a fresh residual audit, ask whether the bottleneck moved,
and re-rank gaps before the next wave.

## Product scorecard intent

A future Final Product convergence scorecard should distinguish structural
correctness from finished product quality. Candidate axes include:

- Learning Scene / spatial architecture
- finished visual/premium quality
- player embodiment
- object-attached HUD
- attention hierarchy
- meaningful motion/state continuity
- interaction quality
- learning effect / repair-transfer-retention loop
- end-to-end product coherence/personalized value
- competitive/desirability/production robustness

Exact axes may be refined by future authority. This protocol does not itself
admit work on any axis.

## Actions / cost policy

Goal: maximum EV per remote run, not maximum iteration count.

Preferred economics once a fast lane exists:

- many read-only/reasoning steps;
- few meaningful renders;
- roughly one fast render per material candidate/wave;
- no PR fan-out during inner loop;
- one heavy final CI/native admission sequence.

Do not spend an Action on every radius, spacing, or cosmetic micro-adjustment.

## Hard anti-drift rules

Even inside a long autonomous Gauntlet:

- one causal mutable layer/hypothesis at a time;
- no broad opportunistic refactors;
- no new dependency without explicit evidence-backed need;
- no Modern Table cosmetic reopening;
- no fabricated Human/retention/real-poker/market claims;
- no competitor asset/code copying;
- do not weaken a valid test/guard merely to obtain GREEN;
- CI/evidence is authority for the claim it actually proves, not an obstacle.

## Stop conditions

Do not work merely to fill time. Stop when any of these is true:

1. no obvious material machine-reducible gap remains;
2. expected marginal EV <= implementation/risk/evidence cost;
3. remaining uncertainty is Human-only, longitudinal, real-poker, retention, or market evidence;
4. owner preference is genuinely required and cannot be derived from authority/North Star;
5. required architecture/dependency exceeds admitted scope;
6. hard execution/infrastructure blocker prevents honest proof;
7. platform/session execution ceiling is reached.

A correct result can be `DO_NOTHING / DIMINISHING RETURN REACHED`.

## Intended activation sequence

This protocol activates only when current authority explicitly allows it. The
planned sequence is conceptually:

1. prove/land cheap remote execution/evidence lane;
2. execute already-admitted V2 `PROTOTYPE -> CANONICAL` production migration without redesign;
3. complete canonical/native proof required by authority;
4. run machine diminishing-return / next-gap adjudication;
5. only if explicitly admitted, activate this long ordinary-Sol autonomous Final Product convergence protocol;
6. HNP/Human remains required wherever current authority requires it.
