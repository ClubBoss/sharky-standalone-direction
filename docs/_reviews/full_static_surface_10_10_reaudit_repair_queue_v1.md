## Cross-surface patterns

1. **Evidence/capture blocker:** W12 payoff and no-W13 images rasterize CTA
   labels as black rectangles; Profile has a separate lower-label raster loss.
   These are evidence defects until source or focused widget proof proves a
   product defect. They block final visual acceptance, not route correctness.
2. **Repeated hub-card grammar (MB-015):** Home, Learn, Practice, Review, and
   Profile all rely on stacked navy-glass containers with similar outline,
   radius, and title/support/CTA cadence. The work should establish role-based
   composition, not apply per-screen card decoration.
3. **Emptiness / dead space:** Practice and Review have the clearest unused
   lower-area cost. The W1/W11/W12 runner uses its space better after Option A;
   no new lower-slot symptom is evidenced in the protected late-route views.
4. **Overload:** Learn detail, Session Summary, and repair/result moments each
   put explanation, proof, and action inside multiple adjacent panels. The
   problem is priority order, not lack of content.
5. **Table hierarchy:** W11 `Transfer` and W12 `Reset` are now distinct. The
   remaining table question is a systemic advanced hierarchy/vertical-allocation
   decision, separate from late-route semantics and separate from capture bugs.
6. **Sharky:** placeholder/dual-register identity remains P1 product debt,
   but it is intentionally deferred while an external designer is working.

## Repair queue

### Wave A — real-text evidence integrity

- **Objective:** make the compact evidence pipeline literal for CTA labels and
  Profile lower tiles, then regenerate only the affected compact packets.
- **Exact scope:** `tools/act0_real_text_surface_capture_v1.dart`, its
  text-repair helper/metadata contract, and focused capture-tool tests; W12
  payoff, no-W13, and Profile capture fixtures.
- **Non-scope:** product copy/layout, Sharky, tablet, routes, W13 policy, and
  any output commit.
- **Likely files:** the capture Dart tool, `screen_review_fast_text_repair_v1.py`,
  existing tooling tests, and one review artifact.
- **Expected tests:** focused capture generation, repair-helper unit checks,
  widget text discovery assertions, `graphify hook-check`, diff checks.
- **Evidence required:** fresh literal compact W12 payoff/no-W13/Profile PNGs
  plus manifest provenance at the implementation HEAD.
- **Executor:** Codex / GPT-5.6 Terra / medium.
- **Stop conditions:** any suspected source-rendering failure, CTA overflow,
  or attempt to edit product UI; stop and split to the affected owner.

### Wave B — cross-hub role composition

- **Objective:** remove MB-015 sameness by giving Home, Learn, Profile,
  Practice, and Review distinct role grammar rather than more cards.
- **Exact scope:** one shared visual-system contract plus only the five active
  hubs, with a compact comparison matrix.
- **Non-scope:** runner/table, session closure, Sharky assets, data contracts,
  route/progression, tablet, and monetization.
- **Likely files:** the five Act0 shell widgets, a small shared primitive if
  source proves one exists, their focused tests, and one review artifact.
- **Expected tests:** affected widget/claim tests, compact capture of core and
  return states, analyzer, graphify, diff checks.
- **Evidence required:** literal compact before/after packet and a role-uniqueness
  checklist; no visual micro-polish without a declared role change.
- **Executor:** Codex / GPT-5.6 Terra / medium.
- **Stop conditions:** changes spread into Sharky, runner, telemetry, or
  require a new state/data model.

### Wave C — repair and session closure hierarchy

- **Objective:** make wrong feedback, repair focus/result, session repair, and
  session summary read as one concise repair-to-proof-to-next-action sequence.
- **Exact scope:** feedback/result/repair/session-summary presentation owners
  and their existing view-model consumers.
- **Non-scope:** semantic repair logic, telemetry, new achievement systems,
  Sharky art, table geometry, and Human QA.
- **Likely files:** `act0_lesson_runner_shell_v1.dart`, existing learning
  evidence/repair projections only if presentation requires them, focused tests.
- **Expected tests:** existing feedback, repair, Session Summary claim-safety
  tests; compact first-week/day-two evidence; analyzer and diff checks.
- **Evidence required:** literal real-text compact evidence for all four
  states, including a wrong-to-repair continuation.
- **Executor:** Codex / GPT-5.6 Terra / medium.
- **Stop conditions:** a proposed change invents proof, persistence, mastery,
  or a new repair model.

### Wave D — advanced table hierarchy decision

- **Objective:** decide whether the mature runner needs one shared vertical and
  semantic hierarchy refinement across W1, W11, and W12.
- **Exact scope:** audit/spec first, then one proven shared runner allocation or
  hierarchy primitive if admitted.
- **Non-scope:** W11/W12 signal semantics (accepted), route state, W13,
  local per-world layout patches, Sharky, and capture tooling.
- **Likely files:** `act0_lesson_runner_shell_v1.dart`, focused compact runner
  tests, late-route signal tests, and a decision artifact.
- **Expected tests:** W1/W11/W12 compact geometry matrix, protected long and
  priced options, feedback/repair branches, analyzer, graphify, diff checks.
- **Evidence required:** literal compact W1/W11/W12 decision and payoff views

- **Executor:** Codex / GPT-5.6 Terra / medium for audit; high only if a shared
  sizing contract proves source-ownership ambiguity.
- **Stop conditions:** no common defect across the three contexts, or a change
