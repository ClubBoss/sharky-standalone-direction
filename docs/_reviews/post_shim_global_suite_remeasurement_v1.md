## Authority Classification Rules

These rules are deterministic and implementable against the current frozen
policy evidence.

| Authority | Deterministic rule | Default blocking behavior |
| --- | --- | --- |
| Tier A | Exact active Act0/release-authority tests only after explicit Tier A lane admission. Phase 0 assigns no global-suite discovery rows to Tier A; active gates remain the focused baseline gates above. | Blocks PR and release. |
| Tier B | Any non-green file whose exact path or longest directory prefix is assigned `B` in `docs/plan/TEST_AUTHORITY_AND_SUITE_LANES_v1.md`: maintained support, compatibility, tooling, Audit Hub, `test/tools`, `test/ui_v2`, and related support rows. | Blocks checkpoint/touched or release-selected lane only. |
| Tier C | Any non-green file whose exact path or longest directory prefix is assigned `C` in `docs/plan/TEST_AUTHORITY_AND_SUITE_LANES_v1.md`: historical/quarantined contracts, dormant tests, old global-suite rows, and owner-review rows. | Non-blocking quarantine/report by default. |
| Tier D | Any non-green file whose exact path or longest directory prefix is assigned `D` in `docs/plan/TEST_AUTHORITY_AND_SUITE_LANES_v1.md`: retired rows such as `test/stubs` after replacement proof. | Excluded by default after replacement proof. |
| UNRESOLVED_OWNER | Use only when the non-green file is absent from the frozen policy and exact owner/import evidence cannot distinguish a maintained support owner from a historical, quarantined, or retired owner. | Non-blocking until explicit owner decision unless active evidence appears. |

The classifier uses longest exact path/prefix match from the frozen policy. It
does not classify by filename alone when policy ownership contradicts the file
name.
