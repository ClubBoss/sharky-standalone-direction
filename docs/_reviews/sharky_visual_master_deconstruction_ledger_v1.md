- table-stage allocation;
- lower learning/action surface allocation;
- decision, feedback, repair and recheck presentation;
- state-family selection;
- runner instruction rail;
- feedback verdict card;
- CTA placement;
- completion and payoff transitions.

The current source contains `Act0RunnerCompositionAllocationV1` and two active composition families:

- `f1TableNative`;
- `f2AnswerList`.

At 1.0× text scale, the lower zone is reserved at approximately:

- f1 compact/canonical/large: 210 / 223 / 241;

## 5. Reconciled historical evidence

The current visual concern is not a new subjective theory. Existing repository audits had already diagnosed the same architecture class:

- fixed lower reservations protect controls but leave void when content is short;
- table size is a downstream result of the reservation, not the root cause;
- table and instructional regions can read as separate visual islands;
- current state/option heuristics do not use actual content demand;
- previous prototypes considered state-aware composition and a stable table plus teaching sheet;
- the narrow `Act0TableSceneV1` / presentation-config seam was chosen to avoid duplicating poker truth.

Current source still contains the shared f1/f2 allocation mechanism, and current evidence still shows the symptom. The previous diagnosis therefore remains relevant, but its old prototype directions are **not automatically admitted**. The next wave must select the smallest current-source repair that closes the current symptom without reviving a broad redesign.

## 6. Systemic visual-cohesion ledger

### VSC-01 — Runner composition allocation and vertical-budget imbalance

**Classification:** `CONFIRMED_SYSTEMIC_HIGH_EV_P2`
**Breadth:** 44 unique current runner visuals are potentially affected.
**Primary owner:** `act0_lesson_runner_shell_v1.dart`.

Visible symptoms:

- table/context consumes most of the screen’s visual mass;
- learning copy is compressed into a comparatively weak lower strip;
- short theory/feedback content leaves large unclaimed dark regions;
- the visual center of gravity remains on the table even when the pedagogical purpose has shifted to explanation or reflection;
- copy-detail states reserve more structure than their actual visible content uses.

Root cause:

- state-family fixed lower reservations;
- table height derived from the remainder;
- lower child can stay top-aligned/intrinsic inside a larger reserved zone;
- state role is not sufficiently reflected in the allocation grammar.

Product impact:

- learner sees the poker context before the lesson takeaway, even in explanation states;
- key feedback looks subordinate or incidental;
- the loop feels technically correct but less authored and less premium.

Admission threshold: met.

### VSC-02 — Weak semantic hierarchy inside feedback / copy-detail surfaces

**Classification:** `CONFIRMED_SYSTEMIC_HIGH_EV_P2`
**Primary owners:** runner feedback card + `act0_shell_tokens_v1.dart`.

Visible symptoms:

- `Correct read`, `Clean read`, source/skill labels and repair-focus labels are very small;
- multiple meta labels can stack before the actual takeaway;
- the learner must parse label → sublabel → title → proof pill → CTA instead of receiving one dominant conclusion;
- important instructional phrases can visually resemble metadata.

Source evidence:

- shared label token is 10px with wide tracking;
- body is 13px, muted text 12px, card title 15px;
- the feedback surface uses the same compact label grammar across several semantic jobs.

Required direction:

- define one dominant outcome/takeaway level;
- allow at most one low-emphasis meta row before it;
- move source/proof identity beneath the takeaway or into a compact evidence row;
- keep CTA visually coupled to the conclusion;
- do not solve through larger text everywhere or by adding more cards.

Admission threshold: met.

### VSC-03 — Insufficient state-role differentiation

**Classification:** `CONFIRMED_SYSTEMIC_HIGH_EV_P2`
**Primary owner:** runner state-to-presentation mapping.

Current states with different learner jobs often share nearly the same lower-surface grammar:

- theory;
- unanswered decision;
- selected decision;
- correct feedback;
- wrong feedback;
- repair focus;
- repair result;
- recheck;
- next-hand transition.

Required state roles:

1. **Observe / theory:** one cue and one compact explanatory hierarchy.
2. **Decide:** question and answers dominate; table remains spatial evidence.
3. **Understand correct:** takeaway and reason dominate; CTA is secondary but adjacent.
4. **Repair wrong:** missed cue and corrected read dominate; retry path is explicit.
5. **Recheck:** same cue, reduced scaffolding, renewed decision emphasis.
6. **Bank payoff:** result and durable learning receipt dominate; table is contextual proof, not the hero.

The implementation must preserve shared components while giving each role a distinct deterministic layout profile.

Admission threshold: met.

### VSC-04 — Table and learning surface read as separate visual islands

**Classification:** `CONFIRMED_SYSTEMIC_P2`
**Primary owner:** runner stage / instruction slot / lower surface seam.

Visible symptoms:

- table ends as one large bounded object;
- the prompt or feedback begins as another independent dark card;
- the ten-point seam does not itself communicate pedagogical continuity;
- the learner can perceive “poker screenshot above, app text below” rather than one guided decision.

Required direction:

- one continuous vertical learning grammar;
- shared alignment axis;
- intentional stage-to-panel transition;
- no new decorative connector;
- preserve table material and geometry.

Admission threshold: met, but should be closed inside the VSC-01/VSC-03 wave rather than through a separate aesthetic PR.

### VSC-05 — Review/Profile proof hierarchy and nested information density

**Classification:** `CANDIDATE_SYSTEMIC_P2 — NOT YET ADMITTED`
**Owners:** `act0_review_shell_v1.dart`, `act0_profile_shell_v1.dart`.

Visible symptoms:

- several nested bordered surfaces compete for attention;
- many all-caps or small meta labels;
- “why now”, miss, current clue, pattern, next rep, proof, earned moment and route proof can all appear within one viewport;
- concrete learner value is present, but the scan order is slower than the Home/Learn scan order.

Why not yet admitted:

- the surfaces remain readable and reachable;
- some density is justified by proof/history value;
- a runner wave may establish hierarchy tokens that improve these screens indirectly;
- the active stage is personalization/learning, so a separate shell polish wave requires fresh EV proof after runner closure.

### VSC-06 — Home/Learn/Practice shell density and action hierarchy

These surfaces are currently the strongest part of the product. Their hierarchy is generally clear and should be used as the reference language for the runner. Do not reopen them broadly.

Potential follow-up is limited to repeated token or layout-rule propagation after the runner change. No independent wave is admitted now.

### VSC-07 — Onboarding stage balance

**Classification:** `OBSERVE / MOSTLY_CLOSED`.

## 11. Anti-loop operating rules

1. One bottleneck family at a time.
2. Maximum two implementation/review cycles per admitted wave.
3. Third cycle only for a proven regression or a new structural fact.
4. Full 135-image review only at baseline, post-systemic convergence and final freeze.
5. Normal PR validation uses 12–24 targeted before/after/neighbor images.
6. No new guard for a hypothetical issue.
7. No new Atlas/tooling feature unless an actual repeated manual operation blocks product work.
8. A wave closes when its measurable DoD passes; it does not remain open because a reviewer can imagine another styling option.
9. Reassess product Top-1 after Wave A rather than automatically continuing visual work.
10. AI Personalization / Learning Effect remains the strategic product priority; visual work is admitted only where it directly raises that learning EV.
