## 7. Core B5 principle

Use only existing deterministic semantics.

Rendering may respond to already-known state such as:

- theory;
- decision;
- eligible/selectable target;
- active player;
- correct feedback;
- wrong feedback;
- causal clue;
- repair target;
- recheck;
- folded/inactive state.

Do not infer new poker meaning.
Do not change truth/evaluation.
B5 transforms visual salience only.

## 8. B5 primary ownership

### 8.1 Salience model

Create one coherent deterministic scene-attention model.

Avoid unrelated per-widget opacity hacks.

The model should represent at least:

- primary;
- supporting;
- ambient / receded;

or an equivalently coherent hierarchy.

### 8.2 Decision attention

During a decision:

- required action context remains immediately visible;
- eligible/actionable objects are distinguishable;
- irrelevant scene decoration/player detail may recede;
- required poker information must not disappear.

Do not expose the correct answer through visual emphasis.
Eligible choices must remain semantically fair/equal where Wave A requires it.

### 8.3 Feedback attention

During correct/wrong feedback:

- verdict hierarchy remains protected;
- causal table clue becomes the scene focal object;
- unrelated poker objects recede enough to reduce search cost;
- object-bound B4 clue remains the exact anchor.

Do not globally hide the hand context.

### 8.4 Repair attention

During repair:

- the exact repair target should be visually easy to reacquire;
- unnecessary competing information may recede;
- repair stays in the same poker scene.

### 8.5 Recheck attention

Recheck must restore enough normal scene context so the learner genuinely
recognises the situation again.

Do not permanently leave the answer highlighted.

### 8.6 Player / environment attention

B3 people and B2 room may recede when they are not the current learning object.
They must remain spatially present.

Do not make the room vanish or turn characters into disabled grey placeholders.

### 8.7 Hero / action attention

Hero cards and actionable controls must remain readable whenever required.
Never sacrifice action clarity for cinematic effect.

## 9. Allowed visual mechanisms

B5 may use deterministic combinations of:

- local luminance;
- contrast;
- saturation;
- opacity attenuation;
- restrained local glow/rim;
- local material response;
- foreground/background attenuation;
- bounded scene dimming;
- bounded depth emphasis.

Selective blur / depth-of-field is allowed only if:

- it materially improves hierarchy;
- it remains readable/accessibility-safe;
- it does not obscure required poker information;
- it stays deterministic;
- it does not become visual spectacle.

Do not use blur merely because a benchmark does.
Highest-EV solution wins.

## 12. B5 iteration strategy

Default TWO strong iterations.

### Iteration 1 - decision + feedback salience model

Goal: establish the central deterministic attention model and prove it in:

- normal decision;
- correct feedback;
- wrong feedback.

The viewer's eye should naturally move to the right information without changing
semantics.

### Iteration 2 - repair + recheck + scene restoration

Goal: prove attention changes correctly through the learning loop:

`feedback -> repair -> recheck`

Recheck must not leak the answer.

Also tune:

- characters;
- environment;
- hero;
- board;
- actions;

so they return to appropriate salience by phase.

Allow iteration 3 only if one major B5 class-level issue survives.
No micro-polish iteration.

## 13. B5 acceptance bar

B5 is `INSUFFICIENT` if:

- every object remains equally loud;
- global dimming makes the scene muddy;
- eligible choices become unfairly weighted;
- feedback clue competes with verdict;
- repair target is still difficult to reacquire;
- recheck visibly gives away the prior answer;
- characters/environment disappear unnaturally;
- cards/actions lose readability;
- the scene becomes a collection of glowing outlines;
- 1.4x text causes attention collisions.

Successful B5 should create a clear glance path:

Decision:

`situation -> actionable choice`

Feedback:

`verdict -> reason -> exact table clue`

Repair:

`exact relevant object / decision context`

Recheck:

`normal recognition context restored`

without changing any underlying learning semantics.
