## Why Wave A exists

P01 exposed one connected novice-experience failure class, not seven unrelated
micro-defects. A novice can see too much small or competing information, skim
teaching content, miss feedback, fail to discover how to answer, encounter
informative table conflicts, and perceive the lesson as a dead end.

Wave A therefore reconstructs the first learning journey as one coherent
vertical experience rather than patching each finding independently.

The reconstructed journey must be materially different from the P01 candidate.
A larger diff is allowed when every changed file belongs to the same bounded
first-learning reconstruction.

## Product intent

Reconstruct this complete first-learning journey:

`ENTRY`
`-> PLACEMENT`
`-> FIRST TABLE READ`
`-> FIRST LESSON ENTRY`
`-> THEORY`
`-> TABLE TASK`
`-> CHOICE`
`-> FEEDBACK`
`-> REPAIR / RECHECK`
`-> CONTINUATION`

The target is one coherent novice learning experience with clear orientation,
discoverable interaction, visible causal feedback, stable table context, and an
explicit path forward.

## Required capability 1 - novice information architecture

Use this rule for the first-learning journey:

`one screen/state = one dominant learner purpose`

Prefer:

- one primary teaching idea;
- concise supporting explanation;
- clear visual hierarchy;
- action-first instruction;
- reduced repetition;
- short causal language;
- meaningful whitespace.

Learner-facing copy may be rewritten when necessary to preserve the same poker
concept with materially lower cognitive load.

Do not expand curriculum, add lessons, or introduce new poker concepts.

## Required capability 2 - interaction language system

Do not patch only one observed task.

Create one coherent interaction grammar for first-learning table tasks. At every
interactive state, a novice must understand:

- what the task is;
- what can be interacted with;
- where to act;
- what happened after the action.

Table-object interaction must be visibly discoverable without revealing the
correct answer.

No observer rescue, hidden gesture knowledge, or poker-app convention may be
required.

## Required capability 3 - Learning Scene V3

Substantially reconstruct the first-learning scene composition.

Target conceptual hierarchy:

`compact teaching/task context`
`-> dominant integrated poker scene`
`-> contextual choice / feedback`
`-> one deliberate continuation action`

The route must cease feeling like:

`UI cards + poker table + more UI cards`

The table is the learning environment, not a decorative insert.

Allowed inside the admitted first-learning route:

- layout allocation changes;
- scene geometry changes;
- hierarchy and grouping changes;
- whitespace changes;
- component placement changes;
- contextual overlays;
- HUD attachment changes;
- lower-surface architecture changes;
- feedback placement changes;
- responsive-behavior changes.

This is a structural visual redesign inside the admitted first-learning route.
It is not permission for a global Modern Table redesign.

## Required capability 4 - Feedback Architecture V2

The existing lower-heavy feedback presentation is not protected.

Preferred conceptual model:

`VERDICT -> SHORT CAUSAL REASON -> VISIBLE TABLE CLUE -> CONTINUE`

Where useful, reinforce the causal clue directly in the table scene.

Example principle only:

`Correct - Check`

`Nobody has bet yet.`

with the causal `No bet yet` signal reinforced spatially in the scene.

Do not blindly copy a competitor implementation.

Do not add dwell timers, forced reading, countdowns, time-gated CTA behavior, or
artificial locks. Hierarchy must earn attention.

## Required capability 5 - table geometry and legibility system

Do not fix only the observed collision symptom.

Establish explicit non-conflicting ownership zones for:

- board;
- pot;
- bets/blinds;
- seats;
- position labels;
- hero;
- hole cards;
- instructional overlays;
- feedback highlights.

Invariant:

> One informative poker object must not obscure another informative poker
> object in supported canonical learning-scene viewports.

Responsive allocation may change substantially inside the first-learning scene.
Modern Table global redesign remains forbidden.

## Required capability 6 - first-lesson landing clarity

P01 found the immediate post-placement surface overloaded.

Do not launch a generic Home redesign.

The immediate first-lesson landing may be simplified or recomposed so one
primary mission dominates:

`continue/start the first learning experience`

Existing navigation may remain available, but it must not compete equally with
the novice's primary next action.

## Required capability 7 - readability

Materially improve directly affected novice-facing readability.

Allowed:

- larger functional typography;
- shorter line length;
- more whitespace;
- fewer simultaneous text blocks;
- clearer title/body distinction;
- reduced secondary copy;
- responsive reflow.

All directly affected states must remain safe under supported viewport and
enlarged-text fixtures.

Do not launch a global typography-system rewrite.

## Design acceptance standard

Passing tests is necessary but not sufficient.

The Wave A candidate must demonstrate an obvious user-visible jump over P01. A
reviewer should identify within seconds:

- less reading burden;
- clearer next action;
- stronger table dominance;
- cleaner table information;
- stronger feedback teaching hierarchy;
- substantially more coherent learning-scene composition.

If the before/after difference requires a diff explanation to appreciate, the
wave is not sufficiently transformative.

## Wave A Definition of Done

All conditions are required.

### Interaction

- P01 required-action ambiguity is structurally eliminated.
- A novice can discover how to answer without observer explanation.
- No answer leakage is introduced.

### Progression

- Valid choices transition deterministically.
- Feedback is obvious.
- Continuation is explicit.
- No affected branch presents a perceived dead end.

### Theory

- Teaching states have one dominant idea.
- Cognitive/text density is materially lower than P01.
- Important meaning is scannable.

### Feedback

- Result and causal clue dominate before continuation.
- Feedback does not depend on forced dwell.
- Correct and wrong states obey the same hierarchy.

### Table

- Relevant informative elements do not collide.
- The table remains the dominant learning anchor.
- Orientation survives decision -> feedback -> repair/recheck.

- First post-placement learning continuation is perceptually obvious.
- No broad Home redesign is performed.

  and clean.
