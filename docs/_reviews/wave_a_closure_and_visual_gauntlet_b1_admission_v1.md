## 8. Required structural systems

### 8.1 Perspective / depth architecture

Create one intentional scene-depth model. At minimum establish:

- background/environment plane;
- far-player plane;
- table plane;
- near-player/hero plane;
- foreground/HUD plane where appropriate.

The perspective model must be coherent across the scene. Do not create arbitrary
fake depth per widget.

### 8.2 Character-ready player volumes

Reserve stable visual volumes/anchors for canonical seats so future player or
character art can be added without moving the entire scene again.

Character art itself may remain placeholder, silhouette, or minimal in B1.

B1 must establish:

- player scale;
- depth;
- anchor;
- overlap ownership;
- visibility;
- active/folded potential;
- hero relationship;
- future art-safe space.

Do not produce the final character family in B1.

### 8.3 Hero ownership

The learner/hero must spatially belong to the scene. Avoid a detached `You` UI
badge floating below a diagram. Create a stable hero zone that future embodiment
can inherit.

### 8.4 Premium table silhouette foundation

The learning-scene table may be structurally refined only where causally
necessary for:

- perspective;
- proportions;
- rail ownership;
- seat alignment;
- scene integration;
- future premium art.

This is not a global Modern Table redesign. Table work must belong specifically
to the canonical learning scene.

### 8.5 Environment / room framing

Establish enough environment ownership that the table no longer floats in empty
UI space.

B1 may introduce:

- bounded background treatment;
- room framing;
- depth planes;
- lighting ownership;
- structural environment placeholders.

B1 does not need final detailed room art. B2 owns premium environment asset
production.

### 8.6 Future object-HUD anchors

Define stable attachment zones/anchors for future:

- stacks;
- bets;
- position labels;
- player status;
- acting indicators;
- clue treatments.

B1 does not fully execute B4, but B1 geometry must not make object-attached HUD
impossible later.

### 8.7 Learning overlay ownership

Wave A's hierarchy must remain intact:

`VERDICT -> CAUSAL REASON -> TABLE CLUE -> CONTINUE`

B1 should make these elements feel spatially integrated with the scene rather
than regressing into generic floating cards.
