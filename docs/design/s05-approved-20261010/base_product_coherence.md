## Authoritative display projection
Production reads ONE existing source snapshot: current World/task, actual gates, original choice/grade, repair assistance, assessed history vs current run, saved mistake/history, current scheduler eligibility and available source task. Summary and Home must read the same projection/reason. If it is unknown, show Loading/Error; never derive empty, unlock, success or due from absence.

The browser stores demo-only state under `sharky-s05-v3-demo-only` and logs SIMULATED_CHOICE. This is a reviewer simulation, not a proposed progression engine, real telemetry or source adapter. It keeps initial wrong + guided correction distinct, and returns to the identical source-reference clue. Existing telemetry/privacy ownership is preserved. Any future admitted implementation must use actual user_choice, correct/error_type and time_to_decision owner, without a second UI receipt. Exact callbacks remain unverified.

## One global interaction grammar
- Primary: deep-ink full-width verb CTA, min 52px height; one strong task per state. Secondary: transparent outline; quiet navigation remains visually subordinate. Destructive reset is not simulated because no side effects were admitted.
- Navigation: Home / Learn / Practice / Review / You. Hide tabs in theory/active decisions/feedback/receipts; back returns to actual context. Avoid accidental assessment by leaving a route. Browser choices commit exactly once because the screen immediately changes.
- Loading: unresolved, no fake progress or ghost tasks; accessible static text under reduce motion. Error: retry without resetting demo state, or safely return to cached path. Unknown source is never empty.
- Locked: explain real requirement and return to current lesson; no purchase promise or bypass. Incomplete: current lesson remains in progress even after one correct read.
- Mistake: selected/expected, causal explanation, exact same clue. Assistance explicitly labeled. Correct: praise the precise interpreted signal, no mastery claim.
- Needs Review: warm status + explicit words; history 3/4 and guided retry count are scoped separately; no false clean result. This native-negative precedent is simulated in the new composition.
- Review: active saved mistake is optional repair; due is independent eligible work; not-due can still have history; empty requires no source items/history. Consumer has no “make due” toggle. Reviewer selects conditional states externally.
- Return: persist actual context, restore before showing a next task; no guilt, day count, streak or fake urgency. Browser reload persistence is a demo proof only.
- Text: complete causal explanation, no line-clamp/ellipsis; one content scroll region, flexible button height, Russian labels. Native reference text itself stays unchanged English; accessible textual choices can display RU and ×1.4 underneath.
- Motion: nonessential 160ms surface transition; loading progress is optional. Reduced-motion stops all animation and communicates the same static status.

## Writing and status semantics
Learner UI says “guided retry”, “answered independently”, “needs review”, “not due”, “saved mistake”, “current lesson”. Provenance, source-owned, conditional fixtures, native limitations and audit identifiers stay in reviewer documentation. No “AI understood your weakness” or guaranteed benefit. Count labels always declare current session, assessed history or guided retry; no isolated success percentage.
